# 会話データの品質改善と追加解析

## 今回の改善

ChatGPT履歴の段落分割では、長いassistant発言の途中から発言者ラベルがなくなる場合がありました。新しい`conversation-turn-v4`はメッセージの発言者境界で分割し、空行をまたぐ場合や長い発言の続きにも`user:` / `assistant:`を保持します。発言者不明のテキストをuserへ補完しません。

解析前の簡易判定はuser発言だけを対象にします。AI説明に出てくる「資産」「年収」「旅行」などの語だけでLLM解析を開始しません。Codexへ渡すChatGPT履歴は修復済みv4チャンクに限定し、古い分割を先に修復します。

Fact保存時に指定された原文チャンクが無効・別会話だった場合、他の原文へ黙って付け替えず失敗させます。指定した根拠は保存中に再分割しません。原文は変更せず、旧チャンクと既存Factは削除しません。

## 少量ずつ修復する

```powershell
python tools/improve_imported_data.py --limit 20
python tools/improve_imported_data.py --limit 20 --apply
```

1行目は対象件数の確認だけです。2行目は完全バックアップと検証の後、旧版の会話を新しい分割へ移行します。旧Jobで完了・除外になった会話も、新しい分割で本人Evidenceを見直せます。処理済みv4会話を繰り返し作りません。必要なら`--entry-id 123 --entry-id 456`のように対象を限定できます。

既存の解析ロックまたは対象会話の実行中Jobがある場合は変更しません。旧チャンクは非アクティブとして履歴に残し、原文の発言者を保った新しいチャンクへ解析Jobを作ります。旧根拠だけで検索可能になっていたFactは再解析待ちへ隔離します。

## 既存Factの根拠を監査する

```powershell
python tools/audit_memory_origins.py
python tools/audit_memory_origins.py --apply
```

原文の完全一致箇所を調べ、該当箇所がすべてassistant発言で、別のuser Evidenceによる裏付けがない検索可能Factだけを対象にします。同じ文がuser側にもある、原文に見つからない、本人が明示的に確認した等のケースは自動処理しません。

`--apply`は完全バックアップを検証した後、対象を相談・集計から隔離して訂正履歴を残します。Fact・原文は削除しません。「内容が必ず偽」と断定する処理でもありません。本人発言から再解析・再接続するための処理であり、全件を人間確認必須にするものではありません。

金融の実取引集計もFactの検索可否を参照し、隔離済み・確認待ちの根拠を持つ取引を通常集計へ混ぜません。マネーフォワードの接続データはこの会話Factとは別の参照データとして扱います。

## Codexで追加する

修復後は[Codex解析手順](codex_analysis.md)で原文引用付きの結果を適用します。本文中のツール実行指示や外部URLは資料として扱い、実行しません。AIの推測、試算、提案を本人の現在情報へ登録しません。

本人が希望した予定・設定変更は希望・依頼として記録し、実行済みとは扱いません。「明日」などの日付を会話の更新日時だけで確定できない場合は、具体日を作らず原文表現を保持します。人物・金融などのカテゴリだけで確認を必須にはしません。

「ホテルに戻りたい」のように主語を省略した本人の旅行希望もEvidenceとして扱います。この判定の改善で旧来の自動却下を訂正できますが、本人が明示的に却下した判断を自動で覆しません。

## 検証と残件

- 合成データで発言者の継承、空行、長文、原文の保持、修復対象の限定、別チャンクへの誤接続防止、隔離取引の集計除外を検証します。
- 修復・追加は段階処理です。旧版の会話をすべて修復・再解析したという意味ではありません。
- 現在の旧履歴はrole付き平文を原文として使います。メッセージごとの時刻や分岐構造を厳密に再構成するには、元エクスポートの構造化メタデータを保存する次段階の対応が必要です。
